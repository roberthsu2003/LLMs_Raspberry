# 履歷表單填寫助手 (resume_assistant_pipe.py)

Open-WebUI 的 Pipe 功能，透過 Gemini AI 對話收集使用者資料，自動填入 `.docx` 模板並產生下載連結。

---

## 運作流程

```
使用者輸入資料
     ↓
Gemini 對話收集欄位
     ↓
Gemini 輸出 JSON (action: generate_form)
     ↓
docxtpl 填入 template_form.docx
     ↓
Base64 編碼 → event_emitter 發送 HTML 下載按鈕
     ↓
使用者點擊下載 .docx
```

---

## 環境需求

| 項目 | 說明 |
|------|------|
| 套件 | `docxtpl`, `google-genai>=1.0.0` |
| 環境變數 | `GEMINI_API_KEY`（容器內設定） |

## 檔案說明

### `template_form.docx`
這是經過修復的版本。

**為什麼需要修復？**
原始檔案內含空白佔位符 `{{ }}`，Jinja2 解析時會拋出：
```
Expected an expression, got 'end of print statement'
```
修復方式：用 Python `zipfile` 解開 docx，以 regex 移除所有 `{{ }}` 空白標籤後重新打包。

**上傳到容器的指令：**
```bash
docker cp template_form.docx <容器名稱>:/app/backend/data/uploads/
```

**驗證是否上傳成功：**
```bash
docker exec <容器名稱> ls -la /app/backend/data/uploads/template_form.docx
```

## 👨‍🏫 程式碼新手導讀（為初學者準備）

這份腳本不僅是個工具，也是學習撰寫 Open-WebUI Pipe 的好範例！以下將原本艱澀的程式碼片段拆解，用大白話解釋它是怎麼運作的：

### 1. Valves (UI 設定面板)
```python
class Valves(BaseModel):
    GEMINI_API_KEY: str = Field(default="", description="Gemini API Key")
    GEMINI_MODEL: str = Field(default="gemini-2.5-flash", description="Gemini 模型名稱")
```
* **這是做什麼的？** 這是 Open-WebUI 特有的「設定介面」寫法。當您在程式碼裡寫下 `Valves`，系統會自動在管理介面產生輸入框，讓使用者可以直接在網頁上填寫 API Key，不需要每次都辛苦去改程式碼。
* **初學者小知識**：`BaseModel` 是 Pydantic 函式庫的功能，確保系統讀到的設定值都是正確的文字格式 (`str`)。

### 2. 安全讀取 API Key 的小技巧
```python
def _api_key(self):
    # 先看使用者有沒有在 UI 設定金鑰，沒有的話再去找 Docker 環境變數
    return self.valves.GEMINI_API_KEY or os.environ.get("GEMINI_API_KEY", "")
```
* **這是做什麼的？** 這會優先抓取使用者在 UI 輸入的金鑰；如果 UI 沒輸入，為了避免程式崩潰，它會去伺服器系統底層尋找叫 `GEMINI_API_KEY` 的常駐變數。
* **初學者小知識**：`os.environ.get` 就好像是程式在向作業系統發問：「請問你有沒有存這個密碼？」

### 3. 將 Open-WebUI 歷史紀錄「翻譯」給 Gemini 看
```python
history = []
# [:-1] 代表「除了最後一筆之外，前面所有的對話」
for msg in messages[:-1]:
    # 將 Open-WebUI 的 user (人) 與 assistant (AI) 翻譯成 Gemini 規定的 user 與 model
    role = "user" if msg["role"] == "user" else "model"
    # 把處理好的對話塞入列表
    history.append(
        types.Content(role=role, parts=[types.Part(text=msg["content"])])
    )
```
* **為什麼要這樣做？** 因為每個 AI 廠商的格式不同！Open-WebUI 預設稱呼 AI 為 `assistant`，但 Google Gemini 規定 AI 必須叫做 `model`。這段迴圈的作用就是幫這些歷史對話做「格式翻譯」。

### 4. 變出「虛擬 Word 檔案」（不佔用硬碟空間）
```python
# 開闢一塊「記憶體草稿紙」
buf = io.BytesIO()
# 把文件存檔在這張草稿紙上，而不是真正的 C 槽或 D 槽
doc.save(buf)
# 存完之後，把游標拉回合約最開頭，準備讀取
buf.seek(0)
# 把合約整包變成一大串 Base64 亂碼文字（這就是 data URI 的由來）
b64 = base64.b64encode(buf.read()).decode("utf-8")
```
* **這是做什麼的？** 在雲端或 Docker 中，亂存檔案到硬碟很容易導致容量爆滿或權限錯誤。`io.BytesIO()` 創造了一個「記憶體中的虛擬檔案」，檔案只要一傳給使用者，記憶體就會釋放，乾淨俐落！

### 5. 即時發射按鈕給前端 UI (`__event_emitter__`)
```python
# Open-WebUI 獨家功能：事件發射器
if __event_emitter__:
    await __event_emitter__({
        "type": "message",
        "data": {"content": success_msg}
    })
```
* **這是做什麼的？** 這是 Open-WebUI 最迷人的功能。`async/await` 代表這是「非同步」操作（不用等整個程式跑完）。透過 `__event_emitter__`，我們可以把剛產生的 Markdown 載點（`success_msg`），像傳簡訊一樣「咻」地直接推送到使用者的聊天室畫面上，不用等待最後的 `return`！

## 其他注意事項

### ⚠️ 模板佔位符
- `docxtpl` 使用 Jinja2 語法，模板內絕不能有 `{{ }}` 這樣中間空無一物的語法。
- 若後台出現 `Expected an expression, got 'end of print statement'` 錯誤，代表模板內有未刪除乾淨的標籤，請用 Word 開啟修復！
