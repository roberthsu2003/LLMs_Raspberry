## 第一章：認識 Functions

### 1.1 什麼是 Functions？

- **定義**：Functions 是 Open WebUI 的「插件」，用來擴充功能
- **特點**：
  - 內建於 Open WebUI，不需額外複雜整合
  - 執行速度快、模組化
  - 純 Python 撰寫，可自由客製
- **與 Tools 的差異**（重要釐清）：
  - **Tools**：模型可「選擇性呼叫」的外部工具（如查天氣、搜尋）
  - **Functions**：在系統層級運作，分為 Pipe、Filter、Action 三種

### 1.2 三種 Functions 類型總覽

| 類型 | 用途 | 在介面上的表現 |
|------|------|----------------|
| **Filter** | 修改輸入／輸出內容 | 對指定模型或全域生效，使用者無感 |
| **Action** | 新增自訂按鈕 | 每則訊息下方出現可點擊按鈕 |
| **Pipe** | 建立自訂「模型」 | 在模型選擇清單中出現，像一個新模型 |

### 1.3 設定位置

- **管理員控制台** → **函式**（或 Workspace → Functions）

## 第二章：Filter Function（過濾器）

> 可整合現有 `過濾器程式碼.md` 內容

### 2.1 核心概念

- Filter 是「攔截器」，在 AI 回答前或後對內容加工
- **Inlet**：送進模型「之前」處理
- **Outlet**：模型回答「之後」處理

### 2.2 流程圖

```
使用者輸入 → [Filter: inlet] → LLM 模型 → [Filter: outlet] → 顯示給使用者
```

### 2.3 Filter vs Tool 比較表

| 比較項目 | Tool（工具） | Filter（過濾器） |
|----------|--------------|------------------|
| 由誰決定執行？ | AI 決定要不要用 | **每一則對話都會經過** |
| 比喻 | 像「技能」 | 像「安檢門」 |
| 作用 | 查資料、計算等 | 修改訊息內容 |

### 2.4 最小可用 Filter 架構

- 類別名稱必須為 `Filter`（Open WebUI 規定）
- `inlet()` 與 `outlet()` 的簽名與回傳格式
- `messages` 結構說明

### 2.5 實作範例

1. **最簡單範例**：空骨架
2. **有感範例**：在 AI 回答結尾自動加文字
3. **進階範例**：繁中轉英文 + 輸出加公司資訊（可引用 `過濾器程式碼.md`）

### 2.6 Valves（可調參數）

- 使用 Pydantic `BaseModel` 定義可調參數
- 在管理介面中讓使用者開關或調整

## 第三章：Action Function（動作按鈕）

### 3.1 核心概念

- 在每則訊息下方新增**自訂按鈕**
- 點擊後觸發自訂邏輯（如摘要、翻譯、複製）

### 3.2 使用情境

- 摘要長訊息
- 翻譯成指定語言
- 一鍵複製、匯出
- 自訂工作流程快捷鍵

### 3.3 基本架構

- 類別名稱：`Action`
- 按鈕顯示位置與觸發流程
- 回傳格式與 UI 顯示方式

### 3.4 實作範例

- 範例一：摘要按鈕
- 範例二：翻譯按鈕

### 3.5 指派方式

- 可指定給特定模型
- 可全域啟用

## 第四章：Pipe Function（管道／自訂模型）

### 4.1 核心概念

- Pipe 建立「自訂模型」或「自訂代理」
- 啟用後會出現在**模型選擇清單**中
- 不一定需要 AI，可整合搜尋 API、天氣、Home Assistant 等

### 4.2 使用情境

- 串接 Google Search API
- 串接多個模型並合併輸出
- 整合非 AI 服務（天氣、資料庫查詢）

### 4.3 基本架構

- 類別名稱：`Pipe`
- 輸入／輸出流程
- 如何「假裝」成一個模型

### 4.4 實作範例

## 第五章：安裝、啟用與指派

### 5.1 安裝 Functions

- **方式一**：透過 Open WebUI 介面安裝（社群函式庫）
- **方式二**：手動匯入（貼上程式碼或上傳檔案）
- 社群函式來源：[Open WebUI Community Site](https://openwebui.com/search)

### 5.2 啟用 Functions

- 安裝後需**手動啟用**
- Pipe：啟用後即出現在模型清單
- Filter / Action：啟用後還需**指派**

### 5.3 指派 Filter 或 Action

- **指定模型**：Workspace → Models → 選擇模型 → 指派 Filter/Action
- **全域啟用**：Workspace → Functions → 「...」選單 → 開啟 **Global** 開關

### 5.4 快速對照表

| 類型 | 啟用後 | 額外步驟 |
|------|--------|----------|
| Pipe | 出現在模型清單 | 無 |
| Filter | 已安裝 | 需指派給模型或設為全域 |
| Action | 已安裝 | 需指派給模型或設為全域 |

## 第六章：安全注意事項與實務建議

### 6.1 安全警告

- Functions 在伺服器上執行**任意 Python 程式碼**
- 僅從**可信來源**安裝
- 匯入前務必**檢視原始碼**，確認無惡意行為
- 惡意 Function 可能：存取檔案系統、竊取資料、破壞系統

### 6.2 實務建議

1. 開發時先在測試環境驗證
2. 使用 Valves 讓參數可調，避免硬編碼
3. 適當的錯誤處理與 log
4. 效能考量：Filter 每則訊息都會執行，避免過重邏輯

### 6.3 為什麼要用 Functions？

- **擴充**：整合新模型、API、資料庫、智慧裝置
- **優化**：調整輸入／輸出以符合需求
- **簡化**：用按鈕或快捷方式提升操作效率

## 注意：官方文件與現有 README 的差異

目前 `Functions/README.md` 寫的是：Filter、Tool、Pipe。

**官方文件**明確區分：

- **Functions**（本講義範圍）：Pipe、Filter、**Action**
- **Tools**：獨立于 Functions，是模型可呼叫的外部工具

建議在講義中釐清：**Tool 不屬於 Functions**，而是另一種擴充機制。本講義專注於 **Pipe、Filter、Action** 三種 Functions。
