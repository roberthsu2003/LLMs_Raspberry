# Open WebUI 工具（Tools）教學講義

**設定位置**：`工作區 > 工具`

系統性拆解 Open WebUI 工作區裡的**工具**能做什麼.

---

## 結論

Open WebUI 的**工具**，本質是：

> **用一個固定結構的 Python 類別，把「可被 LLM 呼叫的功能」包起來。**

掌握以下 3 點就能開始用：

1. **這不是 Flask / FastAPI** — 不用學傳統後端框架
2. **不用自己處理 http request / http response** — 由 Open WebUI 代勞
3. **只要寫「函式 + 描述 + 型別」** — 專注在邏輯與描述

---

## 一、工作區裡的「工具」是在做什麼？

在 **工作區 → 工具** 裡，你其實是在做三件事：

| 功能     | 白話敘述                         |
|----------|------------------------------------|
| **定義工具** | 告訴 AI：「你有這個能力可以用」     |
| **描述工具** | 告訴 AI：「什麼情況該用它」         |
| **實作工具** | 用 Python 實際做事                  |

> 👉 AI 不一定會用你寫的工具  
> 👉 但「描述寫得好」，AI 才會用

---

## 二、必懂的工具功能類型

### 🟢 Level 1：純計算 / 字串處理

**能力特色**

- 不碰外部系統
- 不碰檔案
- 回傳就是字串或數字

**目標**：理解「AI 可以『決定』要不要呼叫我寫的 Python 函式」。

**適合範例**：單位轉換、日期格式化、字串清洗。

---

### 🟡 Level 2：讀取外部資料

**能力特色**

- 呼叫 API
- 讀 RSS / JSON
- 查即時資訊

**亮點**：「AI 說『我要查資料』 → 工具被呼叫」。

---

### 🔵 Level 3：檔案 / RAG / 系統整合（進階）

**能力特色**

- 讀文件
- 向量搜尋
- 接資料庫


---

## 三、「一定要會」的 Python 工具結構

> 👉 **這個結構比語法還重要**

### 工具檔案的最小可用骨架

```python
"""
title: 工具名稱
author: 作者名字
version: 1.0
description: 這個工具在做什麼
"""

from pydantic import BaseModel, Field

class Tools:

    class Input(BaseModel):
        text: str = Field(description="使用者輸入的文字")

    def my_tool(self, text: str) -> str:
        """
        將輸入文字轉為大寫
        """
        return text.upper()
```

### 「心智模型化」

| 元素 | 白話說明 |
|------|----------|
| `class Tools` | 工具容器（一定要有） |
| `class Input` | 給 AI 看的參數說明書 |
| `def my_tool` | 真的在做事的地方 |
| **docstring** | 給 AI 判斷要不要用的關鍵 |

## 四、為什麼 Open WebUI 的工具特別適合教學？

### 和傳統後端的差別

| 項目       | 傳統 Python API | Open WebUI 工具 |
|------------|-----------------|------------------|
| 學 HTTP    | ❌ 要           | ✅ 不用          |
| 學框架     | ❌ 要           | ✅ 不用          |
| 學部署     | ❌ 要           | ✅ 不用          |
| 專注邏輯   | 常被環境分散    | ✅ 可專注        |
| 立即看到 AI 使用 | ❌ 難           | ✅ 第一堂就能成功 |

> 👉 學生不會被「環境」打敗  
> 👉 第一堂就能有成就感
