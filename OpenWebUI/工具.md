# Open WebUI 工具（Tools）教學講義

**設定位置**：`工作區 > 工具`

系統性拆解 Open WebUI 工作區裡的**工具**能做什麼.

---

## 結論

Open WebUI 的**工具**，本質是：

> **用一個固定結構的 Python 類別，把「可被 LLM 呼叫的功能」包起來。**

掌握以下 3 點就能開始用：

1. **這不是 Flask / FastAPI** — 不用學傳統後端框架
2. **不用自己處理 http request / http response** — 由 Open WebUI 代勞
3. **只要寫「函式 + 描述 + 型別」** — 專注在邏輯與描述

---

## 一、工作區裡的「工具」是在做什麼？

在 **工作區 → 工具** 裡，你其實是在做三件事：

| 功能     | 白話敘述                         |
|----------|------------------------------------|
| **定義工具** | 告訴 AI：「你有這個能力可以用」     |
| **描述工具** | 告訴 AI：「什麼情況該用它」         |
| **實作工具** | 用 Python 實際做事                  |

> 👉 AI 不一定會用你寫的工具  
> 👉 但「描述寫得好」，AI 才會用

---

## 二、必懂的工具功能類型

### 🟢 Level 1：純計算 / 字串處理

**能力特色**

- 不碰外部系統
- 不碰檔案
- 回傳就是字串或數字

**目標**：理解「AI 可以『決定』要不要呼叫我寫的 Python 函式」。

**適合範例**：單位轉換、日期格式化、字串清洗。

---

### 🟡 Level 2：讀取外部資料

**能力特色**

- 呼叫 API
- 讀 RSS / JSON
- 查即時資訊

**亮點**：「AI 說『我要查資料』 → 工具被呼叫」。

---

### 🔵 Level 3：檔案 / RAG / 系統整合（進階）

**能力特色**

- 讀文件
- 向量搜尋
- 接資料庫


---

## 三、「一定要會」的 Python 工具結構

> 👉 **這個結構比語法還重要**

### 工具檔案的最小可用骨架

```python
"""
title: 工具名稱
author: 作者名字
version: 1.0
description: 這個工具在做什麼
"""

from pydantic import BaseModel, Field

class Tools:

    class Input(BaseModel):
        text: str = Field(description="使用者輸入的文字")

    def my_tool(self, text: str) -> str:
        """
        將輸入文字轉為大寫
        """
        return text.upper()
```

### 「心智模型化」

| 元素 | 白話說明 |
|------|----------|
| `class Tools` | 工具容器（一定要有） |
| `class Input` | 給 AI 看的參數說明書 |
| `def my_tool` | 真的在做事的地方 |
| **docstring** | 給 AI 判斷要不要用的關鍵 |

## 四、為什麼 Open WebUI 的工具特別適合教學？

### 和傳統後端的差別

| 項目       | 傳統 Python API | Open WebUI 工具 |
|------------|-----------------|------------------|
| 學 HTTP    | ❌ 要           | ✅ 不用          |
| 學框架     | ❌ 要           | ✅ 不用          |
| 學部署     | ❌ 要           | ✅ 不用          |
| 專注邏輯   | 常被環境分散    | ✅ 可專注        |
| 立即看到 AI 使用 | ❌ 難           | ✅ 第一堂就能成功 |

> 👉 學生不會被「環境」打敗  
> 👉 第一堂就能有成就感

## 五、範例題目

### 範例 0：一分鐘懂工具（文字轉大寫）⭐ 先教這個

**一句話**：工具 = 一個 Python 類別，裡面包一個「AI 可以呼叫的函式」。

**學生在聊天裡說**：「幫我把 `hello world` 轉成大寫」

**發生的事**：AI 判斷要用你的工具 → 呼叫你的函式 → 拿到 `HELLO WORLD` → 回給學生。

---

#### 完整程式碼（就這麼短）

```python
"""
title: 文字轉大寫
author: 教學用
version: 1.0
description: 把使用者給的文字轉成大寫
"""

from pydantic import BaseModel, Field

class Tools:

    class Input(BaseModel):
        text: str = Field(description="要轉成大寫的文字")

    def to_upper(self, text: str) -> str:
        """將輸入文字轉為大寫"""
        return text.upper()
```

---

#### 三個重點（講給學生聽）

| 重點 | 說明 |
|------|------|
| **1. class Tools** | 固定寫法，Open WebUI 只認這個名字 |
| **2. Input** | 告訴 AI「要傳什麼進來」（這裡只要一個 `text`） |
| **3. to_upper** | 真的做事的地方，這裡就一行 `return text.upper()` |

> 👉 **工具裡沒有 AI**，只是普通 Python。AI 只負責「決定要不要用」跟「把結果秀給使用者」。

---

#### 為什麼先教這個？

- 只有**一個參數**、**一個函式**
- 不用算數學、不用網路、不用檔案
- 學生馬上能體會：「我寫的 Python 被 AI 呼叫了」

教完這個再教定價、API 會比較順。

### 範例 1：單位轉換（攝氏轉華氏）⭐ Level 1 進階

**一句話**：工具接收一個數值，做單位換算後回傳給 AI。

**學生在聊天裡說**：「30 攝氏是幾度華氏？」或「幫我把 0°C 換成華氏」

**發生的事**：AI 判斷要用你的工具 → 傳入攝氏溫度 `30` → 函式計算 `30 × 9/5 + 32 = 86` → 回給學生「86°F」。

---

#### 完整程式碼

```python
"""
title: 攝氏轉華氏
author: 教學用
version: 1.0
description: 將攝氏溫度轉換為華氏溫度
"""

from pydantic import BaseModel, Field

class Tools:

    class Input(BaseModel):
        celsius: float = Field(description="攝氏溫度（數字）")

    def celsius_to_fahrenheit(self, celsius: float) -> str:
        """將攝氏溫度轉為華氏溫度。公式：華氏 = 攝氏 × 9/5 + 32"""
        fahrenheit = celsius * 9 / 5 + 32
        return f"{celsius}°C = {fahrenheit}°F"
```

---

#### 三個重點（講給學生聽）

| 重點 | 說明 |
|------|------|
| **1. 參數型別** | `celsius: float` 讓 AI 知道要傳數字，不是文字 |
| **2. 公式在函式裡** | 換算邏輯寫在 `celsius_to_fahrenheit` 裡，AI 不用自己算 |
| **3. 回傳字串** | 用 `f-string` 組出人類好讀的結果，例如 `30°C = 86.0°F` |

> 👉 **範例 0 是字串、範例 1 是數字** — 讓學生體會「換一個型別、換一種邏輯」，結構一樣。

---

#### 為什麼教這個？

- 仍是 **Level 1**（不碰網路、不碰檔案）
- 多一個 **`float` 型別**，順便複習 `Input` 的 `Field(description=...)`
- 學生能問「100 攝氏幾度？」馬上得到答案，成就感高
