# Open WebUI 擴充套件完整介紹：工具、函式與 Pipelines

## 📖 總覽：三者如何區分？

在 Open WebUI 中，「擴充」可分為 **工具**、**函式** 和 **Pipelines** 三大類，各自用途與部署方式不同：

| 類型 | 用途 | 執行位置 | 管理位置 |
|------|------|----------|----------|
| **工具** | 擴展 **LLM 能力**，讓模型取得即時資料或執行外部任務 | Open WebUI 主機 | `工作區 > 工具` |
| **函式** | 擴展 **Open WebUI 平台**（過濾器） | Open WebUI 主機 | `管理員控制台 > 函式`  |
| **Pipelines** | 進階工作流程、需大量運算的任務 | **獨立 Pipeline 伺服器** | `管理員控制台 > 設定 > Pipelines` |

**快速理解**:
- **工具** = 給 AI 用的「外掛」，讓它查天氣、搜尋、讀取知識庫等
- **函式** = 給平台用的「外掛」，新增模型、按鈕、過濾邏輯
- **Pipelines** = 需要**單獨部署 Pipeline Server**，適合卸載繁重運算

# 一、工具詳解

## 📖 什麼是工具？

**工具** 是擴展 LLM 能力的 Python 腳本或連線服務，讓 LLM 能執行超出文字生成的功能。啟用後，聊天機器人可執行：
- 🔍 搜尋網路
- 📊 抓取資料
- 🎨 生成圖片
- 🗣️ 使用 AI 語音回覆
- 以及更多功能

工具讓 LLM 能與外部世界互動，取得**即時、真實世界的資料**，這是純預訓練知識無法提供的。

---

## 🧩 工具分類：你使用的是哪種「工具」？

| 類型 | UI 位置 | 最佳用途 | 來源 |
|------|---------|----------|------|
| **原生功能** | Admin/Settings | 核心平台功能 | 內建於 Open WebUI |
| **工作區工具** | `工作區 > 工具` | 使用者創建或社群 Python 腳本 | [社群工具庫](https://openwebui.com/search) |
| **原生 MCP (HTTP)** | `Settings > Connections` | 透過 HTTP/SSE 存取的 MCP 伺服器 | 外部 MCP 伺服器 |
| **MCP via Proxy (MCPO)** | `Settings > Connections` | stdio 型 MCP 伺服器（如 Claude Desktop 工具） | [MCPO 適配器](https://github.com/open-webui/mcpo) |
| **OpenAPI 伺服器** | `Settings > Connections` | REST/OpenAPI 網路服務 | 外部 Web API |

### 1. 原生功能 (Built-in)

這些功能深度整合於 Open WebUI，通常不需外部腳本：

- **Web Search**: 透過 SearXNG、Google 或 Tavily 等引擎
- **URL Fetching**: 使用 `#` 或原生工具從網站提取文字
- **Image Generation**: 與 DALL-E、ComfyUI 或 Automatic1111 整合
- **Memory**: 讓模型記住關於你的事實
- **RAG (Knowledge)**: 查詢上傳文件（使用 `#`）

在**[原生模式](#工具調用模式-default-vs-native)**下，這些會作為 **工具** 供模型調用。

### 2. 工作區工具 (自訂插件)

**Python 腳本**，在 Open WebUI 環境中執行：

- **能力**: 網頁抓取、數學運算、API 呼叫等
- **存取**: `工作區` 選單管理
- **安全性**: 導入前務必審查程式碼，腳本會在伺服器上執行

⚠️ **安全警告**：不應授予一般或不信任使用者工作區工具權限。此權限允許在伺服器上傳並執行任意 Python，可能導致系統被入侵。

### 3. MCP (Model Context Protocol)

開放標準，讓 LLM 與外部資料與工具互動：

- **原生 HTTP MCP**：連接到暴露 HTTP/SSE 的 MCP 伺服器
- **MCPO (Proxy)**：多數社群 MCP 使用 stdio，需透過 [**MCPO Proxy**](https://docs.openwebui.com/features/plugin/tools/openapi-servers/mcp) 橋接

### 4. OpenAPI / Function Calling 伺服器

提供 OpenAPI (`.json` 或 `.yaml`) 規格的網路服務。Open WebUI 可將每個端點視為一個工具。

---

## 📦 如何安裝和管理工作區工具

1. 前往 [社群工具庫](https://openwebui.com/search)
2. 選擇工具，點擊 **Get**
3. 輸入 Open WebUI 實例 URL（如 `http://localhost:3000`）
4. 點擊 **Import to WebUI**

### 安全提示

只導入可信任的工具。這些腳本會在宿主上執行，**只授予受信任使用者「工具」權限**。

---

## 🔧 如何在聊天中使用工具

### 選項 1：即時啟用（特定聊天）

在聊天中點擊輸入區的 **➕ (加號)**，為該會話選擇要啟用的工具。

### 選項 2：預設啟用（全域/模型層級）

1. 前往 **工作區 ➡️ Models**
2. 選擇模型，點擊 ✏️ 編輯
3. 在 **工具** 區段勾選要預設啟用的工具
4. 點擊 **Save**

可使用 [**AutoTool Filter**](https://openwebui.com/f/hub/autotool_filter/) 讓 LLM 自動選擇合適工具。

## 🛠️ 工具調用模式：Default vs. Native

| 功能 | Default Mode | Native Mode |
|------|--------------|-------------|
| **延遲** | 中等/高 | 低 |
| **模型相容性** | 幾乎所有模型 | 需支援工具調用 |
| **邏輯** | 提示詞驅動（Open WebUI） | 模型原生（API/Ollama） |
| **複雜鏈接** | ⚠️ 有限 | ✅ 優秀 |

### 🟡 Default Mode (提示詞基礎)

透過注入提示詞模板引導模型輸出工具請求。

- **相容性**：幾乎所有模型
- **注意**：較慢，多步驟工具鏈較不可靠

### 🟢 Native Mode (Agentic Mode)

利用模型內建的 function calling 處理工具定義與結構化 JSON。

- **速度與效率**：延遲更低
- **多步驟鏈接**：適合代理研究與交錯思考

#### 如何啟用 Native Mode

1. **全域**：**管理員控制台 > Settings > Models** → 目標模型的 **Advanced Parameters** → **Function Calling** 設為 `Native`
2. **單一聊天**：點擊 ⚙️ **Chat Controls** → **Advanced Params** → **Function Calling** 設為 `Native`

#### 推薦模型

- GPT-5、Claude 4.5 Sonnet、Gemini 3 Flash、MiniMax M2.1
- 大型本地模型（如 Qwen 3 32B、Llama 3.3 70B）可試用，效果依模型而異
- 小於 30B 的模型建議使用 Default Mode

---

## 🛠️ 內建系統工具 (Native/Agentic Mode)

啟用 Native Mode 時，Open WebUI 會自動注入系統工具。

### 工具列表摘要

| 類別 | 工具範例 | 需求 |
|------|----------|------|
| 搜尋與網路 | `search_web`、`fetch_url` | `ENABLE_WEB_SEARCH` |
| 知識庫 | `query_knowledge_files`、`list_knowledge_bases`、`view_knowledge_file` | 始終可用 |
| 圖片 | `generate_image`、`edit_image` | `ENABLE_IMAGE_GENERATION` |
| 記憶 | `search_memories`、`add_memory` | Memory 功能 |
| 筆記 | `search_notes`、`write_note`、`view_note` | `ENABLE_NOTES` |
| 聊天歷史 | `search_chats`、`view_chat` | 始終可用 |
| 頻道 | `search_channels`、`view_channel_message` | `ENABLE_CHANNELS` |
| 時間 | `get_current_timestamp`、`calculate_timestamp` | 始終可用 |

詳細參數請參考 [官方文件](https://docs.openwebui.com/features/plugin/tools/)。

### 知識庫工具 vs RAG 管道

`query_knowledge_files` 僅做**簡單向量搜尋**，不包含混合搜尋或重新排序。完整 RAG 請使用 **File Context**（透過 `#` 附加文件或分配知識庫）。

### 停用內建工具

可在 **工作區 > Models** 的 **Capabilities** 中為每個模型開關內建工具。

## 🧠 交錯思考 (Interleaved Thinking)

在 Native Mode 下，高階模型可進行「思考 → 行動 → 思考 → 行動」循環，依序推理、調用工具、評估結果、再決定下一步，適合複雜多步驟任務。

# 二、函式詳解

**函式** 擴展 **Open WebUI 平台本身**，而非 LLM 能力：

- 新增 AI 模型（如 Anthropic、Vertex AI）
- 自訂按鈕與介面
- 實作過濾器（如不當內容過濾）

**管理位置**：`管理員控制台`，僅管理員可設定。  
**導入方式**：從社群一鍵導入，與工具類似。

---

# 三、Pipelines 詳解

## ⚠️ 何時用、何時不用

| 情境 | 建議 |
|------|------|
| 新增 Anthropic、Vertex 等模型或簡單過濾 | 用 **函式** |
| 運行大型模型或複雜邏輯，需卸載運算 | 用 **Pipelines** |

Pipelines 適合**進階使用者**，需要獨立部署 **Pipeline Server**。

---

## 🚀 Pipeline Server 部署

Pipelines **必須**在獨立的 Pipeline Server 上運行，不能只靠在 Open WebUI 主機上設定。

### 方式一：Docker（推薦）

```bash
docker run -d -p 9099:9099 \
  --add-host=host.docker.internal:host-gateway \
  -v pipelines:/app/pipelines \
  --name pipelines \
  --restart always \
  ghcr.io/open-webui/pipelines:main
```

### 方式二：Python 3.11 本地執行

```bash
git clone https://github.com/open-webui/pipelines.git
cd pipelines
pip install -r requirements.txt
sh ./start.sh
```

## 🔗 在 Open WebUI 中連接 Pipelines

1. 前往 **管理員控制台 > Settings > Connections**
2. 點擊 **+** 新增連線
3. 設定：
   - **API URL**：`http://localhost:9099`（Open WebUI 在 Docker 時用 `http://host.docker.internal:9099`）
   - **API Key**：`0p3n-w3bu!`
4. 連線成功後，API Base URL 旁會顯示 Pipelines 圖示

### 管理 Pipeline 設定

前往 **管理員控制台 > Settings > Pipelines**，選擇 Pipeline 並調整 **Valves** 參數。

# 四、Valves 和 UserValves

**Valves** 和 **UserValves** 是工具、Pipelines 和 Filters 的配置機制。

- **Valves**：管理員在工具或函式選單中設定
- **UserValves**：使用者可在聊天會話中設定

使用 Pydantic `BaseModel` 定義，在工具、Filter 或 Pipe 類中聲明：

```python
from pydantic import BaseModel, Field

class Tools:
    class Valves(BaseModel):
        api_key: str = Field("", description="你的 API 金鑰")
    
    class UserValves(BaseModel):
        user_preference: str = Field("default", description="使用者偏好")
```

- **Valves**：在程式碼中直接存取
- **UserValves**：透過 `__user__["valves"]` 存取

# 五、開發自己的工具

### 基本結構

```python
"""
title: 你的工具名稱
author: 你的名字
version: 1.0
license: MIT
description: 你的工具做什麼
requirements: package1, package2
"""

from pydantic import BaseModel, Field
from typing import Dict, Any

class Tools:
    class Valves(BaseModel):
        API_KEY: str = Field(default="key", description="API 金鑰")
    
    def __init__(self):
        self.config = self.Valves()
    
    def your_method(self, param: str) -> Dict[str, Any]:
        """
        方法描述
        :param param: 參數描述
        :return: 返回值描述
        """
        try:
            return {"status": "success", "data": result}
        except Exception as e:
            return {"status": "error", "message": str(e)}
```

### 關鍵要素

- **元資料**：title、author、version、license、description、requirements
- **類別名稱**：必須使用 `class Tools`
- **方法**：含 docstring、型別提示、try-except 錯誤處理
